# Copilot Agent Policies & Requirements

## Policy Change Restriction
- **The AI agent may NOT remove any requirements from this policies file unless explicitly directed to do so by the user.**

## Conversation Streaming Requirement
- **All elements of the conversation, including user participation, must be streamed and recorded in the progress file (`AGENT_PROGRESS.md`).**
- The progress file should capture high-level reasoning, user requests, agent actions, and decisions for full transparency and reproducibility.

## UI/UX Requirements


### SPA & Hamburger Menu Location

### SPA & Login Modal Requirement
- **Web frontend must be a Single Page Application (SPA)**.
- **Login screen MUST NOT be a separate page or route. It MUST be presented as a modal overlay on top of the services (home) page, only when the visitor clicks 'Login' in the hamburger menu.**
- **Hamburger menu MUST appear at the top right corner of the screen on both web frontend and ai-catalog (Android)**.
- Hamburger menu must:
  - Be functional on both platforms
  - Provide navigation to all major pages/screens:
    - Home/Services page (main landing for all users)
    - Email Registration page (guests & admins)
    - Email List page (admin only)
    - Chatbot page
    - Login modal (guests)
- Menu visibility: Show items based on auth state (guest, authenticated, admin)


### Page Separation Rules
- **Home/Services page**: Cards displaying available services (**landing page for all users - guests, authenticated, admins**)
- **Email Registration page**: Form for adding new users (separate route, accessible to guests & admins)
- **Email list page**: Table showing all registered emails (separate route, admin only)
- All three pages MUST be separate routes
- Email list **MUST NOT** appear on home or registration pages
- Registration form **MUST NOT** appear on home page
- Navigation between pages via hamburger menu
- **Both web and Android must start at home page (not login page)**
- **All clients (web, Android, any future clients) MUST show the Home/Services page when accessing the root URL (`[host]:8080/`) regardless of hostname (localhost, 135.148.149.138, or any other)**

### Navigation Testing Protocol
Before marking any UI work complete:
1. Verify hamburger menu works on web frontend
2. Verify hamburger menu works on Android ai-catalog
3. Confirm all menu items navigate to correct pages
4. Verify page separation (list vs registration)
5. Test admin-only restrictions on email list access

### Cityscape Background Requirement
**MANDATORY**: Both web and Android MUST display a cityscape background on the home/services page.

**Android (ai-catalog)**:
- Location: `ai-catalog/app/src/main/res/drawable/cityscape.xml`
- Format: VectorDrawable XML with night sky, building silhouettes, windows
- Usage: Must be referenced in the main app composable (CatalogApp.kt or equivalent) as background
- Verification: `R.drawable.cityscape` should be used as `painterResource` in Image composable with `ContentScale.Crop`

**Web (Angular)**:
- Location: `web-frontend/src/app/home/home.component.ts` CSS styles
- Format: Either inline SVG data URL in CSS background property OR external SVG file in `web-frontend/public/assets/cityscape.svg`
- Design: Must match Android cityscape (dark night sky gradient #1a2332, building silhouettes in dark grays #0d1117/#161b22, lit windows in yellow #ffd700/white)
- Verification: Home container `.home-container` must have `background` property with cityscape image, semi-transparent overlay for card visibility

**Before Any Home Page Changes**:
1. Check that `cityscape.xml` exists in Android drawable resources
2. Check that web HomeComponent has cityscape background in CSS
3. DO NOT remove or simplify existing cityscape backgrounds
4. If cityscape is missing, restore it BEFORE making other changes

## Service Architecture

### Frontend Routing
- All frontend traffic **MUST** route through gateway (port 8080)
- Backend should only see localhost requests from gateway
- CORS handled at gateway level, not backend

### Authentication Flow
- Login works on both web and Android
- JWT tokens persist across page navigation
- Auth state must propagate before making authenticated requests
- Avoid race conditions by not auto-loading data in component init

### Service Endpoints
- Backend: localhost:8081 (internal only)
- Gateway: localhost:8080 (public facing)
- Web frontend: served via gateway as static assets
- MindsDB integration: chatbot tries MindsDB first, falls back to OpenAI/mock

## Code Quality Standards

### Before Each Analysis/Resolution
1. **Consult this policies file first**
2. Update AGENT_PROGRESS.md with reasoning
3. Verify changes don't violate stated requirements
4. Test hamburger menu after any UI changes
5. Confirm page separation after routing changes

### AGENT_PROGRESS.md Streaming Requirements
**MANDATORY**: Stream entire conversation to AGENT_PROGRESS.md in real-time, including:
- **Agent dialogue**: Every question, response, and action from the agent
- **User participation**: All user messages/requests with direct quotes
- **Internal commentary**: Agent's reasoning, analysis, and decision-making process
- **Real-time updates**: Add entries continuously, not in batch summaries
- **Format**: Timestamp, User Question/Comment, Agent Internal Analysis, Agent Actions, Agent Response/Status
- **Context**: For each exchange, capture why decisions were made, what was checked, and what's next
- **Transparency**: Provide enough detail for users to follow the reasoning chain, but avoid raw model internals

### Kotlin/Android
- Use stable, compatible versions (rolled back from cutting edge)
- Don't trust IDE lint errors alone - verify actual build
- Login already works - don't break existing functionality

### Angular Frontend
- GlobalErrorHandler in place for debugging
- Token refresh interceptor handles JWT updates
- Remove auto-load logic that causes race conditions
- Manual actions (buttons) preferred over automatic data fetching
